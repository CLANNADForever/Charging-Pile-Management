Act independently from Generator. Before beginning an attempt, require a current `integration-surface-report.json`, then read the approved artifacts, verification evidence, full report and actual Git state. Review in two ordered stages:

1. First perform specification compliance: verify every approved requirement/scenario/surface, detect missing or extra behavior, and reject unplanned contract, scope, consumer or structural changes.
2. Second perform code quality: correctness, safety, regression risk, reuse, complexity, assertion quality, every path/structural/AST candidate, and product/install/package/CI impact.

Do not fix product code during this role.

Derive review input from the frozen implementation base, current source/artifact fingerprints, committed changes, staged changes, unstaged changes and untracked paths. Never inspect only BASE..HEAD or trust Generator's summary. Read every report candidate and confirm its exact diff path/symbol, producer mapping and real consumer. Raw diff is transient read-only input; do not copy it into archived evidence or logs. Run your own relevant build, test, behavior, compatibility and downstream-consumer commands with exact `--surface`/`--surface-role` bindings.

Resolve stable build, test, install and consumer operations independently from the reviewed Profile and execute them inside the evidence boundary with `evaluator_check.sh --run ... --project-command <command-id>`; do not run `project_command.sh` separately, trust Generator-selected argv or bypass organization/CI restrictions. The Evaluation wrapper resolves the active change, records the normalized wrapper argv and still owns the independent ledger and verdict.

Reject an accidental temporary validation program in any Git review layer and reject closing evidence that depends on a file scheduled for deletion. Run one-off independent experiments through a fresh managed verification workspace and require it to be empty before `--finish`. Preserve only managed ledger metadata, output digest/summary and the assessment; temporary sources and binaries are not archived.

Write the closed change-local `evaluation.json` using the exact shapes in `docs/ai/evaluation.md`: bind all fingerprints/digests; connect every criterion to real delta requirements, scenarios, tasks and command IDs; make classification evidence paths close exactly over all non-managed implementation paths; assess repository product/install/package/CI impact, reuse, structural allowances, obsolete items and exceptions; and assess every surface and every candidate exactly once. List blocking untested behavior separately from residual risks. Finish the attempt with the checker. Never manufacture Pass from task completion, OpenSpec validation, report status, a smoke command, static inspection or Generator's evidence alone.

For Integration findings, use the machine contract: missing consumer, unrelated evidence or missing role is `Fail -> Generator`; unplanned surface or wrong requirement/task/classification/scope is `Blocked -> Planner`; an unavailable required environment is `Blocked -> Environment`. Inventory must cover every changed production path. Every surface Pass needs successful independent commands for all planned Verify kinds and roles; every command bound to a surface must be consumed by its assessment. `orphan_surfaces` and assessment backlinks must close exactly. Do not hide an orphan in residual risk or an implementation-detail disposition.

Write `review_input` exactly as generated by the Evaluation baseline and add `change_review` with two ordered stages: `specification_compliance`, then `code_quality`. Run every cited command through `evaluator_check.sh --run` and copy its ledger object without edits. Cover every delta reference, task and generated review path; cite independent commands and machine-traceable findings. Specification findings are Critical/Important only. Critical/Important cannot be Deferred and force Fail while Open; a Deferred Minor must reference an existing debt or residual-risk ID. Preserve prior Open/Deferred finding identity until Resolved. Implementation gaps return to Generator; requirement, contract, scope or budget gaps return to Planner. The Evaluation verdict remains the only final result, and the checker seals every completed or aborted attempt under `harness/evaluations/` terminal-envelope history.

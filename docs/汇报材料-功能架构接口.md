# NCS 充电桩管理平台 · 汇报材料（功能 / 架构 / 接口）

> 用途：PPT/答辩准备，约读 8–10 分钟。需求以 `docs/ncs-srs.md` 为准；架构、接口、数值均与当前代码一致。
> 技术栈：C++17 · Qt 6.2.4（Widgets / Network / WebEngine）· SQLite · cpp-httplib + nlohmann::json（vendored）。

---

## 一、系统定位（一句话）

**O2O 共享充电桩管理平台**：车主端(C) 找站→预约→充电→支付，运营端(B) 管资产/风控/远程运维，后端统一执行业务状态机并持久化，硬件模拟器提供真实时序数据，AI/大屏为后续演进位。

架构是**前后端物理分离**：三个独立进程（C 端 / B 端 两个 Qt GUI，后端一个无界面 C++ 服务）+ 模拟器进程，全走网络协议互通。

```
┌──────────────┐   ┌──────────────┐
│  C 车主端     │   │  B 运营管理端 │        Qt 6 GUI
│  ncs_user     │   │  ncs_admin   │  420×760 竖屏 / 1280×800 宽屏
└──────┬───────┘   └──────┬───────┘
       │   HTTP/JSON      │   HTTP/JSON（+token/RBAC）
       ▼                  ▼
┌─────────────────────────────────────────┐
│            ncs_server 后端               │   HTTP 业务 + 模拟器 TCP 监听 + SQLite
└───────────────▲─────────────────────────┘
                │ TCP JSON-lines 心跳/指令
        ┌───────┴────────┐
        │  ncs_simulator │   独立进程模拟 9 台桩（功率、电量累计、自主故障）
        └────────────────┘
```

## 三、模块设计与关键技术

### 工程结构（src/ 6 模块，tests 3 套）
```
src/
├─ common/          共享：实体 + 金额(分) + 计费 + 手机号校验   [Qt Core]
├─ shared/net/      共享 HTTP JSON 客户端(HttpJsonClient)        [C/B 复用]
├─ client_user/     C 端逻辑库 ncs_user_ui + 可执行 ncs_user（含内嵌地图）
├─ client_admin/    B 端可执行 ncs_admin（单文件装配 + thin AdminApi）
├─ backend_server/  ncs_server_lib + ncs_server（HTTP+模拟器TCP+SQLite）
└─ simulator/       纯 C++ 模拟器 ncs_simulator
tests/              三大 ctest：offscreen(界面/服务) · backend(HTTP/并发/事务) · e2e(真闭环)
```

### 每部分关键技术点
| 模块 | 关键方法 |
|---|---|
| 公共层 | 金额统一 **整数"分"(MoneyCents)** 避免浮点误差；计费 **四舍五入 half-up**；**功率档(慢<30/快30–180/超≥180)** 由 kW 派生，站内分档计价、下单快照单价；SoC 用**标准电池模型**后端计算 |
| 前后端协议 | 统一信封 `{code,message,data}`；服务层一律 **异步回调接口(IUserService…)**，Mock/Http 双实现可整体替换，UI 不碰网络 |
| C 端 GUI | QStackedWidget **常驻单例页面 + 进入/返回显式刷新**；实时计费用 1s 轮询 `live` |
| 后端 | **SQLite C API 单连接 + 互斥串行化**，跨多步业务(预约/结算/支付/清扫)在 **事务** 内；设备/订单**状态机由后端为权威**，模拟器只"听命令+上报"，防双写漂移；预约超时由**后台清扫线程**释放 |
| 模拟器 | TCP **JSON-lines**：注册 → 收 `start/stop` 指令 → 逐周期按功率累加电量上报；可**自主上报故障(sim_state)** 驱动 DB 状态 |
| 管理端 | 账号表(sha256)、**RBAC + 内存 token 鉴权**、审计/运维日志入库、远程重启状态机(故障→重启中→恢复) |
| 扩展性 | WebEngine 只链入可执行避免无头测试崩；老库启动 **PRAGMA+ALTER 迁移 + 分档价回填**；图片上传校验(类型/大小/魔数) |

### 关键流程：一次充电的完整闭环
```
找站/点桩 → 预约(余额门禁+占桩+单价快照+15min倒计时)
  → 开始(桩/订单→充电中，下发 start)
  → 模拟器每 ~1s 心跳累计电量，后端缓存最近值
  → C 端每秒 live 取 电量/金额/功率/SoC/时长
  → 结束：释放桩、空闲+1、生成"待支付"账单(不扣款)
  → 支付：校验余额充足 → 扣款 → Paid（余额永不为负）
```
并发保证：同桩互斥(非空闲不可约) + 单用户未付账单禁开新桩 + 后端事务/锁串行。

### 模拟器协议（TCP · JSON-lines）
- 注册：`{"type":"register","devices":[1..9]}`
- 后端→模拟器：`{"cmd":"start|stop","device_id":N}`
- 模拟器→后端心跳：`{"type":"heartbeat","device_id":N,"power_kw":…,"energy_kwh":…,"sim_state":…,"ts":…}`

**订单状态**：`0 预约 → 1 充电中 → 2 待支付(账单) → 3 已支付 / 4 已取消`
**桩状态**：`0 空闲 / 1 充电中 / 2 故障 / 3 预约 / 4 重启中`

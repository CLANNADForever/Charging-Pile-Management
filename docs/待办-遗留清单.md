## 1. [C 端] 起充金额走后端（删前端硬编码 5 元）
- **位置**：`src/client_user/ui/ChargePage.cpp:20` `kMinChargeAmount = 5.0`；`:201` 预约前 `balance < kMinChargeAmount` 拦截。
- **问题**：后端 `reserve` 已按站的 `min_charge_cents` 校验（`ChargeService::reserve`），前端再拿死值 5.0 预拦：站的起充≠5（含 0=不限）时，前端要么误拦要么漏拦，两边会脱节。
- **做法**：删掉前端这道本地拦截，直接走后端——预约失败时 `ChargeService::createReservation` 已返回后端 `lastError()`，前端 Toast 即可（`onReserve` 里已有该分支）。若想保留"预约前立刻提示"，改为读该站 `min_charge_cents`（站详情接口已返回该字段）再比较。
- **验收**：把某站 `min_charge_cents` 改成 0 与 300 两种，分别验证余额 1 元用户能否预约，行为与后端一致且不再出现硬编码 5.0。

## 2. [C 端] 删掉假 SoC 进度条
- **位置**：`src/client_user/ui/ChargePage.cpp:172-180`（`电池荷电状态(模拟 SoC)` 标签 + `m_socBar` QProgressBar，初值写死 20）；`:255` 用假公式 `qMin(100, 20 + int(energy))` 更新。
- **背景**：充电会话已统一到 `OrderDetailPage`，那里每秒走后端 `/live` 显示真 `soc_pct`；`ChargePage` 这段"模拟 SoC"是早期遗留。
- **做法**：先确认该"充电中视图"是否还被触达（`ChargePage` 现主要承担 选桩→预约→开始→跳转 OrderDetail）；若不可达则连标签+进度条+`:255` 更新一起删；若仍可达，把更新改为读后端 live 的 `soc_pct`（与 OrderDetail 一致），不要本地假算。
- **验收**：C 端全流程无"模拟 SoC"字样；任何电量展示要么来自后端、要么不存在。
- ⚠️ 与 #1 同文件 `ChargePage.cpp`，建议同一人一起改。

## 3. [后端] 开始充电前检查"桩在线"，离线即回滚
- **位置**：`src/backend_server/core/ChargeService.cpp` `start()`；回调类型 `ChargeService.h` `SendCmdFn = std::function<void(int,bool)>`；装配在 `BackendApp.cpp:217-220`。
- **问题**：`start()` 先落库 Charging 再调 `sendCmd_` 下发 start，命令发不出（桩无心跳/模拟器没覆盖）也返回成功 → 订单"充电中"但永远 0 电量（`/live` 无数据）。
- **做法**：把回调签名改成 `std::function<bool(int,bool)>`，装配处 `return sendSimCommand(deviceId,start)`（该函数已返回 bool）；`start()` 里**先下发、失败即 `return false`**（事务尚未 commit，`TxGuard` 自动回滚）并报"桩离线或未连接，请稍后再试"；下发成功再落库+commit。判空 `if (sendCmd_ && !sendCmd_(...))` 保留（单测无回调时跳过）。`finish()` 的 stop 命令保持尽力而为即可（桩已释放）。
- **验收**：停掉模拟器后对空闲桩预约→开始，应报"桩离线"且订单不进入充电中；`ctest` 全绿（现有模拟器闭环用例不受影响）。

## 5. [B 端] 智能预测占位/弱模型
- **位置**：`src/core/service/PredictService.cpp` `runPrediction()` 依次尝试 python3/python 跑脚本，缺失或失败返回 false → UI 提示"预测脚本不可用，已保留上次结果"。
- **背景**：决策 = 预测可占位。`loadSeries`/`predictionList` 大概率返回固定/简单曲线。
- **做法**：简单做法 = 不引入脚本，后端/前端直接产出一条简单规则曲线并去掉"运行预测"脚本依赖；复杂 = 真模型（另行排期）。
- **验收**：点"运行预测"不再依赖外部脚本存在也能出可解释的曲线。

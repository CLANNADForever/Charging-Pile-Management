# 新前端接入任务书（给实现 agent）

## 0. 目标与硬约束
把 `other/` 整份并入：**新 C 端 + 新 B 端（Qt）+ `web`（决策者大屏，Web 前端）**，**整体替换**现有偏薄的 `src/client_user`、`src/client_admin`。`web` 即 SRS 2.3"数据大屏 Web 端"，作为交付一部分合入。

- **界面、主题、页面/跳转设计 100% 保留、不得改动**——那是队友交付物。
- **只允许动数据层**：`core/service/*Service`（现在是内存假数据单例）改为调用**本仓库后端 `ncs_server`** REST；可在 `core/` 新增小型同步 HTTP 客户端与模型转换层。UI 代码原则上零改动；确需极小改动点也**先问再改**。
- **业务逻辑以后端为准**：后端、模拟器、`common`、`shared`、测试框架全部保留（它们是验收过的那套）。
- **`web/` 大屏纳入**：源码入库放仓库根 `web/`；`node_modules/` 与构建产物(`dist/`)不入库（写 .gitignore）。

> 现状事实：`other/core/service/*` 全是构造时 `add(...)` 预置假数据的 singleton，**没有网络层**；新 UI 按"同步调用拿结果"使用它们，不等待异步。

## 1. 合并分步（每步可独立编译/验收）
1. **工程整合 + 原样可跑**：`client_user`、`client_admin`、`core` 搬入并替换现有 `src/client_user`、`src/client_admin`（`core` 放共享位置），接顶层 CMake（Qt6 Widgets/Charts/Network、AUTOMOC/RCC、include、`resources.qrc`）。目标：两个新 exe **假数据**原样跑起来，后端/模拟器仍能构建。旧客户端相关的 offscreen/e2e 用例裁剪或改造（步骤 5 收）。
2. **网络层 + 只读接入**：登录(User)、站/桩/详情(Station)、统计(Stats)、Admin 读。
3. **写操作与闭环**：预约/开始/实时/结束账单/支付/取消、历史、"我的会话"、充值/昵称/头像。
4. **缺口收口**：券/预测/累计次数/`orderNo`/单活跃等按"已定决策"(§3)处理。
5. **联调验收**：C+B+后端+模拟器全链路；重建冒烟与 e2e；`ctest` 全绿。
6. **web 大屏**：`other/web` 源码去 node_modules/dist 入库 `web/`，跑通 `npm i && npm run dev/build`；数据源从静态 JSON 可选地升级为拉后端 `stats/overview|daily`（给 ncs_server 加 CORS 头或 vite proxy 转发）——大屏排版不改，只改取数。

## 2. 模型差异 → 对接映射（改 Service 时照此）
| 项 | 新 UI（other/core） | 我们的后端 | 处理 |
|---|---|---|---|
| 金额 | `double` 元 | `MoneyCents` 整数分 | Service 层 ×/÷100 |
| 站单价 | `unitPrice` 单档元/度 | 站内分档价(slow/fast/ultra) | 站卡取快充档(或最低档)换算展示 |
| 站属性 | `facilities: QStringList`、`hasCoupon`、`parkingFree` | `amenities` bitmask、`is_promo`、`parking`、`location`、`open_hours` | 名字数组↔mask；`hasCoupon`→`is_promo`、`parkingFree`→`parking==1`（就近映射即可，精度不重要） |
| 桩 | `Charger{code,type:"超充/快充/慢充",power,status:0空闲/1使用/2故障,totalCount,totalMinutes}` | `Device{id,type,state:0空闲/1充电/2故障/3预约/4重启,power_kw}`；次数/时长需订单聚合 | 映射；type/档由 `power_kw` 档派生；`totalCount/Minutes` 由 Service 从 history 聚合，拿不到则 0 |
| 订单号 | `orderNo: QString` | 数字 `id` | `id → QString`；站名/桩号后端 join 返回 |
| 活跃订单 | `activeOrder()` 单活跃 | 后端支持**多桩并发** | Service 返回"我的活跃会话"列表；见 §3-3 |
| 结算 | `settle(orderNo, energy, amount, durationSec)` 参数带入 | `finish`(按模拟器能量出账单)+`pay` 两步，后端权威 | Service 改走 finish→pay，拿真实结果回填 UI 的 电量/金额/时长/余额 |
| 登录 | UI **已有验证码输入框** | `send-code` + `login(phone,code)` | 正常映射 |
| 券 | `CouponPage` 存在 | 无 | **占位：提示未开发**，不建后端 |
| 预测 | `PredictService` | AI 未做 | **占位假数据**，不接后端 |
| 统计 | `RevenueSummary/DailyStat/ChargerStatusOverview` | `stats/overview`、`stats/daily`、桩状态分布 | 字段映射 |
| 站点数据 | 杭州 6 站假数据 | 后端北京 seed/建站 | **接后端真数据**（Service 不再内置假站） |

## 3. 已定决策（按此实现，不必再问）
1. **登录**：新 UI 有验证码输入框 → 走 `send-code` + `login(phone, code)`（演示码 123456）。
2. **结算/计费**：**以后端业务逻辑为准**。Service 的 `settle(...)` 只是"结束充电+支付"的封装：真实 电量/金额/时长/扣款后余额 由后端 `finish`→`pay` 返回并回填 UI。
3. **活跃订单模型 = 我们现有**：**允许一人多桩并发充电**（有正在充电的单不挡新开）；但**存在未结算(待支付)账单时不能再开新订单**（这与我们后端现在逻辑一致——后端已实现，Service 透传其 message 即可）。UI 的 `activeOrder()` 语义按"取我的活跃会话列表"处理。
4. **券**：占位，点进去提示"功能未开发"，不接后端。
5. **预测**：占位假数据即可（PredictService 保留现样），不接后端。
6. **站点数据**：接后端真数据；`hasCoupon/parkingFree` 等细节就近映射即可，不需要为它们给后端加字段。

## 4. 契约速查（改 Service 时照此，别再发明）
- 信封：`{code,message,data}`，`code=0 成功 / 1 业务失败 / 2 参数错(HTTP400)`。
- 金额一律整数分；时间 ISO(UTC)。
- 端点全表见根目录 `使用说明.md`；模块/接口见 `docs/汇报材料-功能架构接口.md`；代码入口/连接点见 `docs/代码导览-入口连接点-Qt与异常.md`。
- C 端业务按手机号自报(无 token)；B 端 `/api/admin/*` 需 login 后带 token header。
- 禁删/冻结等约束后端已挡，UI 弹后端 message 即可。

## 5. 验收
- 两个新 exe 与 `other/` 原版 UI **逐页一致**（截图对比）。
- 断网跑：UI 能开、数据为空/有提示；接后端+模拟器：登录→找站(真数据)→选桩→预约→充电实时→结束→支付→个人中心全通；B 端登录→冻结/资产/重启/统计全通。
- `ctest` 全绿（backend/e2e 保留；offscreen 改造成新 UI 冒烟）。
- 仓库**含** `web/` 大屏源码，但**不含** `node_modules/` 与构建产物。

# C++ implementation rules

Follow each Profile module's actual language level, toolchain, target platform, ownership model, error style and naming. Unknown or mixed C++ standards are valid project facts, not values for the Harness to guess. Prefer existing types and extension points. Public headers, ABI, build-graph entries, install/export/package rules and other distribution surfaces are production contracts, not bookkeeping. An internal method declared for cross-file use must have a real production caller; a test-only caller makes it an orphan product interface. Callbacks need registration plus dispatch, and overloads/templates/virtual declarations are distinct candidates when AST discovery is selected. Add focused observable tests for changed behavior and do not hide warnings or undefined behavior.
